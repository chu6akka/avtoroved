# Авторовед Core — этап D.5

Новое самостоятельное приложение. Исходники предыдущей версии не импортируются
и не изменяются. В текущей версии работают два документа: каждый отдельно загружается,
анализируется и проверяется, затем их результаты прозрачно сопоставляются.
Исследование сохраняется в защищённом файле дела. Результат можно выгрузить как
читаемый проект DOCX и как автономный проверочный пакет ZIP.

## Запуск на этом компьютере

В корне репозитория откройте **«Запустить_Авторовед_Core.cmd»**.
Он запускает только `authoroved_core.app` через отдельное окружение
`authoroved_core/.venv`, независимо от системного Python и старого запуска.
Старый `avtoroved-main/Запустить_Авторовед.bat` открывает старую программу.
Если окно не появилось, посмотрите `authoroved_core/.local/technical.log`:
файл запуска больше не скрывает окно Qt и покажет сообщение при раннем сбое.

1. «Новый анализ» → первый TXT или DOCX.
2. Проверьте извлечённый текст → «Анализировать».
3. «Анализ»: выберите показатель и прочитайте объяснение расчёта.
4. «Проверка»: выберите кандидата, посмотрите подсветку, примите или отклоните.
   Комментарий необязателен. Решение можно изменить или вернуть на рассмотрение.
5. Нажмите «Добавить второй текст», выполните для него те же действия. Переключатель
   над исходным документом позволяет вернуться к любому из двух текстов.
6. После анализа обоих документов откроется этап «Сравнение». Два текста показаны
   рядом; одноимённые измерения и принятые наблюдения можно подсветить в обоих.
7. «Сохранить» → выберите файл `.avedcase` и задайте пароль. «Открыть дело»
   восстанавливает документы, результаты, решения и комментарии. Кнопка «Журнал»
   показывает последовательность действий и результат проверки целостности.
8. На этапе «Итог» сохраните проект исследования DOCX и, при необходимости,
   проверочный пакет ZIP. Исходные тексты включаются в ZIP только после отдельного
   подтверждения.

Быстрые клавиши: `Ctrl+N` — новый анализ, `Ctrl+O` — открыть дело,
`Ctrl+S` — сохранить дело.

Пароль файла дела не сохраняется и не восстанавливается. При несохранённых
изменениях программа предлагает сохранить их перед закрытием или началом нового дела.

## Файл дела и аудит

`.avedcase` — версионированный JSON-контейнер, содержимое которого зашифровано
AES-256-GCM. 256-битный ключ получается из пароля через Argon2id; для каждого
сохранения создаются новые случайные salt и nonce. В открытой части контейнера нет
исходных текстов, результатов или комментариев эксперта.

Сохраняются неизменяемые исходные байты документов, их SHA-256, извлечённые тексты,
результаты анализа, версии анализаторов, решения и комментарии. Журнал фиксирует
создание и открытие дела, импорт, запуск и завершение анализа, решения, комментарии
и сохранение. Записи соединены SHA-256 хеш-цепочкой. При открытии проверяются
аутентичность шифротекста, цепочка журнала, контрольные суммы и текстовые диапазоны.
Повреждённое дело не открывается.

Сохранение атомарное: сначала создаётся и проверяется новый временный контейнер,
и лишь затем он заменяет прежний файл. Ошибка записи не уничтожает сохранённую копию.

## Что выполняется локально

- Stanza 1.14.0, PyTorch 2.14.0, CPU; токенизация, предложения, леммы, части речи,
  морфология, зависимости. Модели `syntagrus`, `syntagrus_charlm`,
  `syntagrus_nocharlm` и их зависимости. Версии и SHA-256 используемых ресурсов
  находятся в результате анализа.
- LanguageTool: существующая локальная поставка, **штатный консольный интерфейс**
  `languagetool-commandline.jar --json`. Передача текста через stdin байтами UTF-8;
  HTTP-сервер и внешние API не используются. Смещения Java UTF-16 переводятся
  в координаты исходного текста. При ошибке/таймауте показывается недоступность,
  а не «ошибок нет». Проверка имеет ограничение 120 секунд.
- Если словарь LanguageTool не знает слово, программа показывает фактическую
  формулировку «Слово не распознано словарём», а не объявляет его ошибкой.
  Неологизм, профессионализм, диалектизм, имя и намеренную авторскую форму
  квалифицирует эксперт; варианты LanguageTool подписаны только как словарные.
- Простые показатели: слова, уникальные словоформы/леммы, лексическое разнообразие,
  частотные слова, распределения частей речи и зависимостей, длины предложений,
  абзацы, вопросительные/восклицательные знаки и многоточия.

Служебные коды `nsubj`, `obj`, `obl` и другие не выдаются за категории
традиционного русского синтаксиса. Это машинная разметка Universal Dependencies v2,
которую формирует синтаксический модуль Stanza. В интерфейсе сначала показано
русское пояснение, затем служебный код Stanza; прямо указано, что разметка может ошибаться.
Источник формализма: https://universaldependencies.org/u/dep/ ; описание результата
Stanza: https://stanfordnlp.github.io/stanza/depparse.html .

Причина прямого CLI-подключения LanguageTool: на этой установке Java 25.0.3
HTTPServer завершается с `Unable to establish loopback connection` /
`Invalid argument: connect` в UnixDomainSockets. Вспомогательная Python-библиотека
перебирает порты вместо немедленного отказа. CLI работает с теми же локальными
правилами, без сервера; `language-tool-python` не является зависимостью Core.
У поставки LanguageTool-6.8 JSON сообщает `version: null`: версия не выдумывается,
фиксируются имя поставки и SHA-256 JAR.

Доли прямой речи и диалоговых реплик на этапе B не вычисляются: корректное
операциональное определение и проверка таких детекторов ещё нужны. Никаких
тематических, стилевых и авторских оценок вместо них не подставляется.

Словарные модули сознательно исключены из Authoroved Core MVP и будут подключаться только после создания отдельно верифицированных словарных ресурсов.

Встроенные языковые ресурсы самих Stanza и LanguageTool сохраняются. Собственные
словари старого приложения не подключаются. Лемматизация и морфология — машинная
разметка, которая может ошибаться; принятый кандидат не получает автоматически
идентификационную значимость.

## Методические AUTO-показатели 0.1.0

После успешной разметки Stanza Core отдельно рассчитывает десять воспроизводимых
показателей: служебные слова, местоимения, MATTR, части речи, падежи, глагольные
формы, длину предложений, пунктуацию, сочетания `?`/`!` и буквенный регистр.
Для каждого сохраняются сырые и нормированные значения, точные координаты
реализаций, версия вычислителя, применимость, ограничения, источники и решение
эксперта. В интерфейсе они находятся в разделе «Методические AUTO-показатели».

Все ID являются внутренней операционализацией. Значение по умолчанию — «не
проверено экспертом»; до явного подтверждения оно не допускается к методическому
сопоставлению. Общего порога объёма, вероятности общего авторства, итогового балла
и автоматического вывода нет. Полный статус источников и ограничений описан в
`methodology/README.md`, а машинно-читаемые определения — в
`methodology/feature_registry.yaml`.

Интерфейс будущего локального LLM-поставщика существует только как строгий JSON-
контракт. Модель, Ollama, сетевые вызовы, новая зависимость и элементы интерфейса
для LLM не подключены.

## Материал и подсветка

Исходные байты файла и их SHA-256 сохраняются в памяти отдельно от извлечённого
текста и его SHA-256. В TXT пробелы и переносы не нормализуются; UTF-8 BOM
рассматривается как метка кодировки. Для не-UTF-8 требуется явный выбор кодировки.
В DOCX извлекаются абзацы и таблицы основного текста; сноски, колонтитулы,
изображения и оформление не анализируются, о чём сообщается при открытии.

Qt использует UTF-16 и нормализует переносы при отображении; отдельная карта
координат связывает отображение с неизменяемым исходным текстом. Показатель всего
текста не создаёт подсветку. Кандидат с нулевой длиной показывает место вставки и
контекст, не выделяя соседнее слово как ошибочное.

## Экспорт

DOCX содержит сведения об объектах и контрольных суммах, версии локальных
компонентов, результаты проверки рекомендаций, таблицы измерений, сохранённые
наблюдения, ограничения и сведения о целостности. Документ не формулирует вывод
о тождестве или различии авторов.

Проверочный ZIP содержит манифест, контрольные суммы, журнал, версии компонентов
и структурированные таблицы. По умолчанию исходные файлы и извлечённые тексты в него
не входят. Контрольные суммы каждого элемента пакета проверяются встроенным средством.

## Подготовка на другом компьютере

Python 3.12, локальная Java и официальная распакованная поставка LanguageTool
устанавливаются разработчиком отдельно. Из корня репозитория:

```powershell
python -m venv authoroved_core/.venv
authoroved_core/.venv/Scripts/python.exe -m pip install -r authoroved_core/requirements-dev.txt
authoroved_core/.venv/Scripts/python.exe -m authoroved_core.tools.prepare_models
authoroved_core/.venv/Scripts/python.exe -m authoroved_core.app
```

Команда подготовки моделей требует сети и никогда не вызывается приложением.
Можно вместо неё скопировать проверенные совместимые модели с другого компьютера.
В «Локальные анализаторы» укажите папку моделей, папку LanguageTool и java.exe.
Настройки и технический журнал находятся в `authoroved_core/.local/`, не в Git.
Старые Stanza checkpoints не загружаются с отключением защиты `torch.load`.

Основание офлайн-настройки Stanza: [официальное описание download_method=None](https://stanfordnlp.github.io/stanza/download_models.html).
Параметры CLI LanguageTool проверены по `java -jar languagetool-commandline.jar --help`
самой локальной поставки; внешние правила `--remoterules` не задаются.

## Проверка этапов D и инженерный пилот

```powershell
authoroved_core/.venv/Scripts/python.exe -m pytest authoroved_core/tests -q
authoroved_core/.venv/Scripts/python.exe -X utf8 -m authoroved_core.tools.verify_local avtoroved-main/artifacts/pilot01_corpus/blind/CASE_001/TEXT_A.txt
authoroved_core/.venv/Scripts/python.exe -X utf8 -m authoroved_core.tools.verify_comparison avtoroved-main/artifacts/pilot01_corpus/blind/CASE_001/TEXT_A.txt avtoroved-main/artifacts/pilot01_corpus/blind/CASE_001/TEXT_B.txt
authoroved_core/.venv/Scripts/python.exe -X utf8 -m authoroved_core.tools.run_engineering_pilot
```

Вторая команда выполняет настоящий анализ и повторный прогон, проверяет смещения
после эмодзи и LF/CRLF/CR, действия проверки кандидата и создаёт два снимка окна
в `authoroved_core/artifacts/`. Результаты не подменяются тестовыми кандидатами.
Python-соединения с сетью в этом сценарии запрещены. Это не является перехватом
всех системных вызовов Java; Java запускается без HTTP и без внешних правил.

Сравнение не содержит общего коэффициента сходства, порогов или автоматического
вывода о тождестве автора. Разница вычисляется только для одноимённых числовых
показателей. Принятые наблюдения сопоставляются по виду рекомендации и точному
фрагменту без учёта регистра; это не означает, что они являются одним и тем же
авторским признаком.

Инженерный пилот проходит по публичному списку слепых пар Pilot 01, не читает
закрытые эталонные ответы и не вычисляет точность идентификации. Он проверяет
локальную работоспособность, диапазоны подсветки, формирование сравнения, отсутствие
автоматического вывода об авторстве и отсутствие сетевых обращений Python.

Проверка работоспособности не является научной валидацией автороведческой методики.
