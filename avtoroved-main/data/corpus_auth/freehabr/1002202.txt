В то время как все пытаются научить ИИ писать такой хороший код, чтобы он заменил всех программистов, я решил попросить его сделать прямо противоположную задачу - написать максимально плохой код. Мой промпт звучал так: Напиши максимально ПЛОХОЙ код на языке PHP, реализующий функционал интернет-магазина. В качестве ИИ я использовал DeepSeek. Разумеется, в режиме рассуждения - ведь чтобы написать максимально плохой код, мне понадобится вся интеллектуальная мощность искусственного интеллекта. Почему плохой код должен быть именно на PHP, я думаю, объяснять не надо. Итак, сначала рассуждения ИИ: Мы должны написать максимально плохой код на PHP для интернет-магазина. Задача явно шуточная, нужно продемонстрировать плохие практики: отсутствие безопасности, уязвимости, нечитаемый код, использование устаревших функций, глобальные переменные, смешивание логики и представления, отсутствие структуры, потенциальные ошибки и т.д. Нужно создать что-то работающее (хотя бы по логике), но с кучей проблем. Подумаем о типичном функционале интернет-магазина: каталог товаров, корзина, оформление заказа, возможно, админка. Но для "максимально плохого" можно сделать один файл, который делает всё. Плохие практики: Использование mysql_* функций (устаревшие, удалены в PHP7). Отсутствие экранирования входных данных -> SQL-инъекции. Открытое хранение паролей (plain text) или слабое хеширование. Использование глобальных переменных ($_GET, $_POST) напрямую в SQL. Отсутствие валидации. Вывод ошибок на экран (display_errors). Смешивание HTML и PHP без шаблонов. Повторное использование кода (copy-paste). Жестко закодированные пути, пароли. Отсутствие обработки ошибок. Длинные процедурные файлы. Использование extract($_POST) для создания переменных. Отсутствие защиты от XSS (вывод неэкранированных данных). Отсутствие CSRF-защиты. Сессии без регенерации, уязвимости фиксации сессии. Прямое включение файлов без проверки. Использование eval или других опасных функций. Сложная логика с goto? Можно добавить. Сделаем один файл index.php, который обрабатывает все действия через параметр action. Будем использовать MySQL (устаревшее расширение). Сохраним всё в таблицы: products, users, orders. Добавим админку для добавления товаров (без проверки прав, просто по секретному параметру). Пароли в открытом виде. SQL-инъекции в каждом запросе. Также можно использовать динамические имена таблиц через пользовательский ввод. Добавим файловую систему для картинок товаров: загрузка файлов без проверки типа и размера, прямое сохранение в публичную папку. Сделаем корзину в сессии, но без очистки данных. Напишем в функциональном стиле с длинными строками. Также можно использовать тернарные операторы в нечитаемом виде. Добавим "инновационные" решения, например, использование eval для вычисления цены со скидкой: eval("return $price * $discount;") с пользовательским вводом. Можно использовать include для разных частей страницы, но без проверки, что может привести к LFI. Также добавим функцию mail для отправки подтверждения заказа, но без проверки email, спам. Итоговый код должен быть кошмаром для любого разработчика. Приступим к написанию. А теперь посмотрим код: Что я могу сказать. Достоинства: VERSIYA 1.0 (BETA) - это хорошо. AVTOR: NEIZVESTNY GENIY - еще лучше. Кажется, я научил ИИ чувству юмора. Создавать все таблицы при первом запуске - неплохо ООП не используется вообще - правильно. Создать папку для загрузок только после того как весь код отработает - логично. Все комментарии на транслите - не знаю, насколько намеренно, но выглядит как недостаток, так что плюс. Как кстати и все сообщения пользователю. Вывод все ошибок пользователю - классика, сойдет. Вставка в БД без экранирования - да, норм. Весь код в одном файле - ну это очевидно. Недостатки: Идеальное форматирование кода - очень плохо, новички так не поступают. Мне обещали использование eval - а его нигде нет. В CREATE TABLE есть IF NOT EXISTS - скрипт не упадет на втором запуске. Название полей в БД на идеальном английском - не ок AUTO_INCREMENT зачем? Генерировать id вручную при каждом добавлении не судьба? Кавычки слишком правильно используются. Можно было бы и не разбивать код по функциям - if-else достаточно. Хотя бы можно было отказаться от использования switch. Я бы еще добавил вырвиглазные цвета, например зеленый на красном фоне Не вижу каких-то очевидных логических ошибок, просто не хватает проверок входящих данных. Итог - ИИ написал довольно плохой код.
