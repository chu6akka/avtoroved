# Автороведческий анализатор v5

Десктопное приложение для судебно-автороведческой экспертизы русскоязычного
текста (PyQt6, Stanford Stanza). Ядро программы — **экспертный протокол**:
воспроизводимый четырёхстадийный процесс идентификационного исследования,
в котором программа готовит и фиксирует данные, а вывод формулирует эксперт.

Изолированный контур `validation/` проверяет обнаружение кандидатов,
воспроизводимость, вспомогательные тематический и стилевой слои и парный
хронометраж. Он не рассчитывает «точность авторства» и не меняет production-
пороги. Формат и запуск описаны в [протоколе валидации](docs/validation_protocol.md).

## Экспертный протокол

Четыре стадии по несущей методике (Рубцова и др., 2007, с. 80–85):

| Стадия | Вкладка | Что происходит |
|---|---|---|
| 1. Пригодность | «Пригодность» | Формализуемая оценка объёма, извлечения текста, цитат/повторов, автокоррекции, устной речи и сопоставимости пары. Ограничения и инструментальные предупреждения предъявляются эксперту и не определяют допустимую форму вывода |
| 2. Раздельное исследование | «Раздельное исслед.» | Профиль КАЖДОГО текста до всякого сравнения: 4 группы признаков (смысловые, текстологические, языковые, психолингвистические), кандидаты ошибок через управляемый фильтр детектора |
| 3. Сравнительное исследование | «Карта признаков» → «Сравнительное исслед.» | Эксперт утверждает кандидатов в признаки (принят/отклонён/сомнителен/не учитывать), затем сопоставляет пары по уровням индивидуализации НН/НС/НСВ |
| 4. Оценка и вывод | «Вывод и заключение» | Методический контроль показывает наблюдаемые количества, справочные условия и ограничения материала; выбранную форму и обоснование фиксирует эксперт; экспорт заключения в DOCX по структуре Приложения 1 |

**Принцип**: программа не выбирает, не рекомендует и не блокирует форму
экспертного вывода. Она обеспечивает измерения, методический контроль,
стадийность и фиксацию; итоговую оценку совокупности выполняет эксперт.

**Воспроизводимость**: sha256 всех входных файлов и экспортированных
заключений; версии программы, LanguageTool, правил детектора и хэш конфига
фильтра — в журнале действий (`audit_log`); решения эксперта хранятся
append-only; словарные базы версионируются при обновлении.

Вспомогательные вкладки: «Материалы» (импорт DOCX/TXT, слои текста, журнал),
«Инспектор токенов» (карточка каждого слова: морфология, частотность НКРЯ,
регистровый слой, тональность, внешние словари по клику).

**Служебная лексика (Огорелков)** — квантитативный слой протокола: частоты
(ipm) закрытого перечня из 11 служебных лексико-грамматических классов
(местоимения, союзы, предлоги, частицы, вводные слова) с нормированием по
частотному словарю Ляшевской–Шарова. Работает на всех стадиях: в раздельном
исследовании даёт кандидатов признаков по классам и по отдельным леммам с
отклонением от нормы, в сравнительном — покатегорийное и полемное
сопоставление пары, в заключении — отдельный подраздел DOCX. Отдельная
вкладка показывает те же величины для одиночного текста.

## Аналитические вкладки (вне протокола)

Статистика (TTR, hapax, POS-биграммы), Языковые навыки (ошибки и степени
развития навыков), Морфология, ИИ-детектор (GigaCheck).

Часть прежних вкладок (Стратификация, Тематика, НКРЯ, Тональность, старое
Сравнение, старый Отчёт, Профиль автора) **архивирована**: модули работают и
питают протокол данными, но их страницы скрыты из навигации. Вернуть любую —
ключ `archived_pages` в `config.json`.

## Установка и запуск

```bash
pip install -r requirements.txt
python main.py
```

При первом запуске Stanza скачает модель русского языка (~500 МБ, один раз).
Для проверки ошибок LanguageTool в локальном режиме нужна Java 8+
(без неё работают собственные правила пунктуации). Сборка в exe:
`python -m PyInstaller --clean --noconfirm avtoroved.spec` → `dist/avtoroved/`.

## Структура проекта

```
avtoroved-main/
├── main.py                  # Точка входа
├── protocol/                # Экспертный протокол
│   ├── db.py                #   SQLite: проекты, документы, слои, признаки,
│   │                        #   решения (append-only), сравнения, выводы, журнал
│   ├── ingest.py            #   Импорт материалов, sha256, слои текста
│   ├── suitability.py       #   Стадия 1: пригодность
│   ├── profile.py           #   Стадия 2: профиль по 4 группам
│   ├── feature_map.py       #   Отбор признаков экспертом
│   ├── comparison.py        #   Стадия 3: сопоставление по НН/НС/НСВ
│   ├── conclusion.py        #   Стадия 4: методический контроль и фиксация решения эксперта
│   ├── report.py            #   Экспорт заключения (DOCX, Приложение 1)
│   ├── detector_filter.py   #   Фильтр ложных срабатываний детектора
│   ├── detector_filter.json #   Конфиг фильтра (правится без кода)
│   ├── token_card.py        #   Карточки токенов
│   └── lexicon_update.py    #   Обновление словарных баз (с бэкапом и версией)
├── analyzer/                # NLP-движки и словари (Stanza, метрики, ошибки,
│                            # стратификация, тематика, частоты НКРЯ, RuSentiLex)
├── ui/                      # PyQt6: главное окно, вкладки, диалоги
├── data/                    # Словарные базы (freq, senti, лексиконы)
├── tests/                   # pytest (100+ тестов протокола)
├── scripts/                 # Сборка exe, валидация детектора
└── avtoroved.spec           # PyInstaller
```

## Методическая основа

### Идентификационное ядро

- **Рубцова И. И., Ермолова Е. И., Безрукова А. И. и др.** «Комплексная
  методика производства судебно-автороведческих экспертиз» — М.: ЭКЦ МВД
  России, 2007. — *Несущая методика*: шкала степеней развития навыков
  (с. 13), дедупликация ошибок (с. 14), четыре стадии исследования
  (с. 80–85), уровни индивидуализации НН/НС/НСВ и правило вывода (с. 85).
- **Вул С. М.** «Судебно-автороведческая идентификационная экспертиза:
  методические основы» — Харьков: ХНИИСЭ, 2007. — *Количественная база*:
  дифференцированные пороги навыков, решающее правило по грамматическому и
  лексико-фразеологическому навыкам (с. 38).
- **Моисеева Т. Ф., Огорелков И. В.** «Судебная автороведческая экспертиза» —
  М.: РГУП, 2021. — *Стадийность и покатегорийные пороги* числа признаков
  для категорического/вероятного вывода (с. 89–93).
- Методические рекомендации СЭУ Минюста России — соотносимая ведомственная
  методика (допуски сопоставления навыков, с. 19).

### Диагностические подходы (вне идентификационного ядра)

- Назарова Т. В., Манянин П. А., Громова А. В. и др. — методические подходы
  ЭКЦ МВД России к диагностике (2021), лексическая стратификация.
- Litvinova et al. (2015–2016) — POS-биграммы профилирования автора.
- Колокольцева Т. Н. — признаки интернет-коммуникации.
- GigaCheck (SberDevices, [arXiv:2410.23728](https://arxiv.org/abs/2410.23728)) —
  детекция ИИ-текста; результаты вспомогательные.

### Словарные базы

- Частотный словарь НКРЯ (Ляшевская, Шаров); RuSentiLex (labinform.ru);
  Химик В. В. «Большой словарь русской разговорной экспрессивной речи»;
  лексикон стратификации (12 251 лемма, 13 пластов).

## Требования

- Python 3.10+ (сборка тестировалась на 3.13), Windows / macOS / Linux;
- RAM: 4 ГБ+ (8 ГБ+ с GigaCheck); ~3 ГБ диска с моделями;
- Java 8+ — опционально, для локального LanguageTool.
