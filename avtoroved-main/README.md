# Автороведческий анализатор v5

Инструмент судебно-автороведческой экспертизы текста на русском языке.
Превосходит Lingster 3.0 по функционалу, реализован на PyQt6.

## Экспертный протокол (основной режим работы)

Полный цикл идентификационной экспертизы по методике Рубцовой (2007)
и ЭКЦ МВД России (2021) — от импорта материалов до заключения в DOCX.
Все данные хранятся в локальной базе SQLite рядом с программой; каждое
действие эксперта пишется в append-only журнал (audit_log) — история
решений никогда не редактируется и не удаляется.

| Стадия | Вкладка | Что происходит |
|--------|---------|----------------|
| Импорт | **Материалы** | Загрузка спорных текстов и образцов (TXT/DOCX), SHA-256, происхождение, жанр; оценка качества извлечения текста |
| 1. Пригодность | **Пригодность** | Проверка объёма и сопоставимости пары; ограничения могут блокировать категорическую форму вывода |
| 2. Раздельное исследование | **Раздельное исслед.** | Автопостроение профиля по 4 группам признаков (смысловые, текстологические, языковые, психолингвистические); кандидаты признаков с оценкой идентификационной ценности |
| — отбор | **Карта признаков** | Эксперт принимает/отклоняет кандидатов (append-only решения, полная воспроизводимость) |
| 3. Сравнительное исследование | **Сравнительное исслед.** | Сопоставление принятых признаков пары: совпадения/различия, уровень индивидуализации (НН/НС/НСВ) |
| 4. Оценка результатов | **Вывод и заключение** | Рекомендация формы вывода по правилу методики (с.85–86), фиксация вывода экспертом, экспорт заключения в DOCX с иллюстрациями признаков и технической справкой воспроизводимости |
| Инструмент | **Инспектор токенов** | Карточка любого слова: морфология, пласты, ошибки, внешние словари |

Заключение DOCX строится по Приложению 1 методики: вводная часть →
ИССЛЕДОВАНИЕ (4 стадии, подтверждённые признаки иллюстрируются цитатами
из обоих текстов) → ВЫВОДЫ → техническая справка (версии, хэши).
Каждый экспорт регистрируется в базе с SHA-256 файла.

## Аналитические модули

| # | Функция | Описание |
|---|---------|----------|
| 1 | **Морфология** | POS-теги, леммы, морф. признаки (Stanford Stanza) |
| 2 | **Статистика** | TTR, hapax, POS-биграммы (Litvinova et al., 2015–2016) |
| 3 | **Ошибки и навыки** | 4 категории ошибок, степени по С.М. Вул (2007); слой фильтрации детектора + локальный LanguageTool |
| 4 | **Интернет-коммуникация** | 12 маркеров сетевого идиолекта |
| 5 | **Стратификация лексики** | 13 пластов, 12 251 лемма (ЭКЦ МВД России, 2021) |
| 6 | **ИИ-детектор (GigaCheck)** | Локальная модель SberDevices, подсветка интервалов |
| 7 | **Тематические словари** | 10 областей: право, медицина, IT, экономика и др. |
| 8 | **Грамматические запросы** | Поиск паттернов `NOUN ADJ`, `VERB * NOUN`, wildcards |
| 9 | **Обновление словарей** | Догрузка словарных баз из открытых источников (меню «Файл») |

Часть страниц (Стратификация, Тематика, НКРЯ, Тональность, старое
Сравнение, старый Отчёт, Профиль автора) переведена в архив: расчёты
сохранены и питают профиль раздельного исследования и инспектор токенов,
но из сайдбара убраны. Вернуть страницу: список `archived_pages`
в `config.json` рядом с программой.

## Установка

```bash
pip install -r requirements.txt
```

При первом запуске Stanza автоматически скачает модель русского языка (~100 МБ).

## Запуск

```bash
python main.py
```

## Структура проекта

```
avtoroved-main/
├── main.py                      # Точка входа
├── protocol/                    # Экспертный протокол
│   ├── db.py                    # SQLite: проекты, документы, признаки, аудит
│   ├── ingest.py                # Импорт TXT/DOCX, SHA-256, оценка извлечения
│   ├── suitability.py           # Стадия 1: пригодность объектов
│   ├── profile.py               # Стадия 2: профиль по 4 группам признаков
│   ├── feature_map.py           # Отбор признаков экспертом (append-only)
│   ├── comparison.py            # Стадия 3: сопоставление пары
│   ├── conclusion.py            # Стадия 4: правило формы вывода
│   ├── report.py                # Экспорт заключения DOCX
│   ├── detector_filter.py       # Фильтрация срабатываний детектора ошибок
│   ├── token_card.py            # Карточка слова для инспектора токенов
│   └── lexicon_update.py        # Обновление словарных баз из интернета
├── ui/
│   ├── main_window.py           # Главное окно (PyQt6), сайдбар, архив страниц
│   ├── styles.py                # Тёмная / светлая тема
│   ├── tabs/                    # Вкладки анализа и протокола
│   └── dialogs/                 # Пакетная обработка, словари, обновление баз
├── analyzer/
│   ├── stanza_backend.py        # NLP: Stanford Stanza
│   ├── metrics.py               # Статистика + POS-биграммы
│   ├── errors.py                # Анализ ошибок (70+ правил)
│   ├── export.py                # Экспорт DOCX (аналитические отчёты)
│   ├── gigacheck_detector.py    # ИИ-детектор (HuggingFace)
│   └── thematic_dicts.py        # Тематические словари
├── data/
│   ├── lexicon_stratified.json  # 12 251 лемма (стратификация)
│   └── thematic/                # 10 JSON-словарей по областям
├── tests/                       # pytest: протокол, детекторы, словари
└── requirements.txt
```

```
stanza>=1.8.0        # NLP (Stanford)
```

> **GigaCheck** работает локально без интернета после первой загрузки модели (~1–4 ГБ).
> Результаты GigaCheck носят вспомогательный характер и не заменяют лингвистический анализ.

## Методическая основа

- Рубцова И.И. и др. «Комплексная методика производства автороведческих экспертиз» (ЭКЦ МВД России, 2007)
- Назарова Л.С., Маняни В.А., Громова А.Н. «Методика автороведческой экспертизы» (ЭКЦ МВД России, 2021)
- Вул С.М. «Судебно-автороведческая идентификационная экспертиза» (2007)
- Litvinova et al. (2015–2016) — POS-биграммы для профилирования автора
- «Правила русской орфографии и пунктуации» (АН СССР, 1956)
- Химик В.В. «Большой словарь русской разговорной экспрессивной речи» (2004)
- GigaCheck — SberDevices, [arXiv:2410.23728](https://arxiv.org/abs/2410.23728)
