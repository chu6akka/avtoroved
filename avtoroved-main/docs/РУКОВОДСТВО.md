# Руководство пользователя «Авторовед» v5

Программа для судебно-автороведческой экспертизы русскоязычных текстов:
полный цикл идентификационного исследования «спорный текст ↔ образец» —
от импорта материалов до отчёта исследования в DOCX, с фиксацией каждого
действия эксперта в журнале.

Методическая основа: Рубцова И.И. и др. «Комплексная методика производства
автороведческих экспертиз» (ЭКЦ МВД России, 2007); Назарова Л.С. и др.
«Методика автороведческой экспертизы» (ЭКЦ МВД России, 2021); Вул С.М.
(2007); методика СЭУ Минюста; Моисеева/Огорелков (2021).

---

## 1. Установка и первый запуск

### Требования

- Python 3.10+ (Windows / macOS / Linux);
- 2 ГБ ОЗУ (8 ГБ+, если используется ИИ-детектор GigaCheck);
- ~500 МБ на диске для моделей NLP.

### Установка

```bash
pip install -r requirements.txt
python main.py
```

Windows: можно запускать двойным кликом по `Запустить_Авторовед.bat`.

При первом запуске:

1. **Stanza** (NLP-разметка) автоматически скачает модель русского языка
   (~100 МБ) — нужен интернет только один раз.
2. **Детекторы ошибок работают офлайн из коробки** — собственные правила
   программы (орфография по словарю OpenCorpora, -тся/-ться, согласование
   определений, пунктуация, тавтология и плеоназмы) не требуют ни Java,
   ни интернета. Плюс встроенная офлайн-база правил LanguageTool
   (`data/lt_rules_ru.json`: 200+ правил и ~290 словарных замен, LGPL) —
   обновляется скриптом `tools/import_lt_rules.py` при наличии интернета. **LanguageTool — необязательное дополнение**, расширяющее
   покрытие: если установлена Java 17+, поднимется локальный LT-сервер
   (статус внизу сайдбара, кнопка «↻ Подключить LT»). В экспертном протоколе
   LT работает **строго локально** — материалы дела на внешние серверы не
   отправляются. Состав детекторов фиксируется в признаках: профили,
   построенные с LT и без него, автоматически считаются несопоставимыми
   по общим признакам (защита от ложных выводов).
3. **PDF-импорт** доступен, если установлен пакет `pypdf`
   (`pip install pypdf`); иначе принимаются TXT и DOCX.
4. **GigaCheck** (ИИ-детектор, необязателен) при первом использовании
   скачает модель 1–4 ГБ.

### Где лежат данные

- `protocol.db` (рядом с программой) — база экспертного протокола: проекты,
  документы, признаки, решения, журнал. Резервная копия = копия этого файла
  **плюс** исходные файлы материалов.
- `config.json` (рядом с программой) — настройки интерфейса
  (тема, список скрытых вкладок `archived_pages`).

## 2. Обзор интерфейса

Слева — сайдбар навигации, справа — рабочая область.

- **▶ Анализировать** (`Ctrl+Enter`) — запускает разовый анализ текста из
  поля «Текст для анализа». Работает для аналитических вкладок (раздел 6);
  вкладки экспертного протокола берут тексты из базы, и поле ввода на них
  скрыто.
- Разделы сайдбара: **АНАЛИЗ ТЕКСТА** (быстрые аналитические вкладки),
  **ИНСТРУМЕНТЫ**, **СЕРВИС** и **ЭКСПЕРТНЫЙ ПРОТОКОЛ** (основной режим).
- Внизу сайдбара — статусы бэкендов (LT, спеллер, SBERT) и кнопка
  «📖 Справочник словарей» (`F4`).

Меню:

- **Файл** → «📦 Пакетная обработка…» (несколько файлов за раз, DOCX-отчёт),
  «📚 Обновить словарные базы…» (раздел 7), выход;
- **Вид** → тёмная / светлая тема;
- **Визуализация** → диаграмма частей речи, heatmap POS-биграмм;
- **Справка** → справочник словарей (`F4`), о программе.

## 3. Экспертный протокол: рабочий цикл

Порядок вкладок в сайдбаре повторяет стадии методики. Пропускать стадии
нельзя: пока не проведена предыдущая, следующая либо пуста, либо ограничит
форму вывода. Каждое действие фиксируется в журнале (audit_log) — история
решений append-only, не редактируется и не удаляется.

### Шаг 1. «Материалы» — проект и импорт

1. «➕ Создать проект» — имя дела (и ФИО эксперта).
2. Перед импортом каждого файла укажите:
   - **Происхождение**: `рукопись`, `печатная_машинка`, `цифровой`,
     `опубликованный`, `расшифровка_устной_речи`. Это влияет на надёжность
     признаков: у цифровых/опубликованных текстов орфография и пунктуация
     считаются искажёнными автокоррекцией; расшифровка устной речи
     ограничивает письменно-речевые признаки.
   - **Жанр** (письмо, статья, пост…) — проверяется сопоставимость пары.
3. «📄 Добавить спорный текст» / «📑 Добавить образец» — импорт TXT, DOCX
   (текст извлекается и из таблиц) или PDF. Файл получает SHA-256,
   текст проходит NLP-разметку и сохраняется слоями в базу.
   Пустое или мизерное извлечение помечается сразу.
4. «🧾 Открыть журнал» — просмотр audit_log проекта.

### Шаг 2. «Пригодность» — гейт перед исследованием

Кнопка «🔄 Пересчитать пригодность» оценивает каждый документ и каждую пару
спорный↔образец. Вердикты: **пригоден** / **пригоден_с_ограничениями** /
**непригоден**.

Проверки документа:

| Проверка | Порог | Флаг |
|---|---|---|
| Извлечение текста | пусто/мизер | «извлечение» → непригоден |
| Объём | <100 словоформ; <150 — ненадёжно | «малый_объём» / «объём_ненадёжный» |
| Предложения | <10 | «мало_предложений» |
| **Знаменательные словоформы** (NOUN/VERB/ADJ/ADV/PROPN) | спорный <100, образец <600 | «объём_знаменательных» |
| Цитаты | >30% символов | «цитаты» (чужая речь) |
| Повторы | >30% словоформ | «повторы» (шаблонность) |
| Происхождение | цифровой/опубликованный | «автокоррекция» |
| Устная речь | происхождение или маркеры (эээ, «как бы», (нрзб)) | «устная_речь» |

Проверки пары: одинаковость жанра, происхождения, сопоставимость средней
длины предложения (различие более чем вдвое → флаг).

Любой флаг-ограничение ставит **blocks_strong_conclusion** — категорические
формы вывода для пары будут понижены до вероятных. «Непригоден» блокирует
их всегда.

### Шаг 3. «Раздельное исслед.» — профиль каждого текста

Выберите документ → «🧩 Построить профиль». Профиль строится по каждому
тексту отдельно, до всякого сравнения, и складывается из:

- **счётчиков** (Σ) — объективные показатели: архитектоника, TTR, hapax,
  доли частей речи, регистровые слои, стилевые маркеры, интернет-маркеры,
  доминирующие темы;
- **кандидатов признаков** (◆) — срабатывания детектора ошибок
  (офлайн-детекторы: пунктуация, орфография по словарю, -тся/-ться,
  согласование, тавтология/плеоназмы; плюс локальный LanguageTool,
  если доступен — после слоя
  фильтрации `protocol/detector_filter.json`) с подгруппой, фрагментом
  и автооценкой идентификационной ценности; каждый помечен
  «требует проверки»;
- **общих признаков** — степени развития навыков: орфографического,
  пунктуационного, грамматического, лексико-фразеологического и общий
  уровень грамотности. Степень (высокая <4, средняя 4–6, низкая >6 ошибок
  на 200 словоформ — Рубцова 2007, с. 13; дубли одного типа считаются
  одной ошибкой, с. 14) и точное число ошибок на 200 словоформ видны в
  значении. При флаге автокоррекции орфографический и пунктуационный
  общие признаки имеют пометку низкой надёжности.

Пересборка профиля идемпотентна (старый удаляется), решения эксперта по
карте признаков при этом сохраняются.

### Шаг 4. «Карта признаков» — отбор экспертом

Кандидаты признаков (счётчики и общие признаки сюда не попадают — они
объективны) проходят ручной отбор:

- **✔ Принять** — признак войдёт в сравнительное исследование; можно
  скорректировать идентификационную ценность и оставить примечание;
- **？ Сомнителен**, **✘ Отклонить**, **∅ Не учитывать** — в сравнение
  не идёт;
- **↺ Сбросить решение** — вернуть в нерешённые.

Каждое решение пишется в append-only журнал решений и переживает
пересборку профиля (ключ решения — стабильный хэш содержимого кандидата).

### Шаг 5. «Сравнительное исслед.» — сопоставление пары

1. Выберите пару спорный ↔ образец → «⚙ Сопоставить автоматически».
   Автоматика — только черновик:
   - принятые признаки с одинаковым содержанием в обоих текстах →
     черновик «совпадение»; признак в одном тексте → «только_у_…»;
   - **общие признаки** сопоставляются по числу ошибок на 200 словоформ
     с допусками методики СЭУ Минюста (с. 19): ±2 для грамматического и
     лексико-фразеологического, ±4 для орфографического и пунктуационного.
     В пределах допуска → «совпадение», за допуском → «различие»; вердикт
     по каждому навыку (совпадает / выше в спорном / ниже в спорном)
     показан в сводке под таблицей.
2. Каждую позицию эксперт подтверждает: «✔ Подтвердить (тип/уровень)…» —
   тип (совпадение / различие / только_у_…), **уровень индивидуализации
   НН / НС / НСВ** (Рубцова 2007, с. 11; по возрастанию) и примечание.
   Различие можно признать **объяснимым** (жанр, временной разрыв,
   состояние автора) — флажок в диалоге, письменное пояснение обязательно:
   такая позиция остаётся в отчёте с пометкой, но исключается из правила
   рекомендации формы вывода. «↺ Сбросить подтверждение» возвращает
   позицию в черновики (история решения сохраняется).
3. Сводка под таблицей показывает счётчики по типам и уровням, прогресс к
   суммарному порогу ≥20 (Рубцова, с. 85) и недоборы по **корзинам
   Огорелкова** — покатегорийным минимумам подтверждённых совпадений
   (Моисеева/Огорелков 2021, с. 89–93):

| Корзина | Категорический | Вероятный |
|---|---|---|
| смысловые | 3 | 2 |
| текстологические | 5 | 3 |
| языковые: лексические | 10 | 5 |
| языковые: стилистические | 10 | 5 |
| языковые: синтаксические | 10 | 5 |
| языковые: орфографические+пунктуационные | 5 | 3 |
| психолингвистические | 5 | 3 |

Пересопоставление не трогает подтверждённые позиции.

### Шаг 6. «Вывод и заключение» — оценка результатов и отчёт

Вкладка показывает **автоматическую рекомендацию** формы вывода с
пояснением по пунктам. Правило (в порядке приоритета):

0. **Гейты стадийности**: если объект пары признан непригодным —
   рекомендация НПВ (исследование по паре не проводится); если стадия
   пригодности не проводилась вовсе — категорические формы недоступны,
   пока она не проведена.
1. **Решающее правило Вула** [Минюст, с. 19; Вул 2007, с. 38]: степень
   грамматического и/или лексико-фразеологического навыка в спорном тексте
   **выше**, чем в образце, за пределами допуска → категорический
   отрицательный. Орфографический и пунктуационный навыки в правиле не
   участвуют (ненадёжны из-за автокоррекции). Работает по объективным
   общим признакам — подтверждения позиций не требует.
2. Подтверждённое **различие на уровне НН** → категорический отрицательный.
3. Различия на НС/НСВ (или без уровня) → вероятный отрицательный.
4. Только совпадения:
   - все три уровня + суммарно ≥20 + **все** корзины Огорелкова →
     категорический положительный;
   - половинные корзины → вероятный положительный;
   - ниже половинных → НПВ, недобранные группы перечислены в пояснении.
5. Нет данных → НПВ (не представляется возможным).

Флаг blocks_strong_conclusion из стадии пригодности понижает категорические
формы до вероятных (причина указывается).

Рекомендация — **только подсказка**. Форму вывода выбирает и фиксирует
эксперт («📌 Зафиксировать вывод»); при несогласии с рекомендацией
обязательно письменное обоснование. Каждая фиксация сохраняется в истории.

«📄 Экспорт отчёта исследования (DOCX)» выгружает **вставляемую
исследовательскую часть** заключения (не целостное заключение): раздел
ИССЛЕДОВАНИЕ — объекты с SHA-256, четыре стадии, подтверждённые признаки
с цитатами-иллюстрациями из обоих текстов, оценка результатов — и
техническую справку воспроизводимости (версии, хэши конфига). Титул,
реквизиты дела и раздел ВЫВОДЫ эксперт оформляет в своём документе.
Экспорт возможен и до фиксации вывода (тогда в стадии 4 — живая
рекомендация). Каждый экспорт регистрируется в базе с SHA-256 файла.

### «Инспектор токенов» — карточка слова

Выберите документ, режим подсветки (части речи / регистровые слои /
частотность НКРЯ / без подсветки) и кликните по любому слову: карточка
покажет морфологию, лемму, регистровый слой, частотность, найденные ошибки
и ссылки во внешние словари.

## 4. Уровни и степени: шпаргалка

- **НН / НС / НСВ** — уровни индивидуализации навыка по возрастанию
  (Рубцова 2007, с. 11). Проставляются экспертом при подтверждении позиции
  сравнения. Различие на НН — самое сильное основание отрицательного
  вывода; для категорического положительного нужны совпадения на всех
  трёх уровнях.
- **Степени развития навыка** (общие признаки): высокая — менее 4 ошибок
  на ~200 словоформ, средняя — 4–6, низкая — свыше 6 (Рубцова 2007, с. 13).
- **Идентификационная ценность** кандидата: низкая / средняя / высокая —
  автооценка детектора, корректируется экспертом в карте признаков.

## 5. Типовые ситуации

- **Образец слишком короткий.** Пригодность покажет «объём_знаменательных»
  — категорический вывод недоступен. Запросите дополнительные образцы
  (суммарно от 600 знаменательных словоформ каждый).
- **Спорный текст грамотнее образцов.** Сработает правило Вула —
  рекомендация «категорический отрицательный» с указанием навыка и дельты.
- **Много совпадений, но одна группа.** Категорической формы не будет:
  сводка сравнения и пояснение рекомендации перечислят недобранные корзины.
- **Цифровой текст (мессенджер, соцсеть).** Флаг «автокоррекция»:
  орфографические/пунктуационные кандидаты и общие признаки помечаются
  ненадёжными, правило Вула по ним не работает, категорические формы
  заблокированы.
- **Не согласен с рекомендацией.** Выберите свою форму и запишите
  обоснование — без него фиксация не пройдёт. И рекомендация, и ваше
  решение останутся в истории.

## 6. Аналитические вкладки (без протокола)

Для быстрого разового анализа: вставьте текст в поле «Текст для анализа»
и нажмите ▶ (или `Ctrl+Enter`).

- **Статистика** — TTR, hapax, длины, POS-биграммы;
- **Языковые навыки** — ошибки по категориям и степени развития навыков;
- **Морфология** — токены с леммами и грамматическими признаками;
- **Сравнение** — 6 метрик сходства двух текстов (архив);
- **ИИ-детектор** — GigaCheck, подсветка машинно-сгенерированных интервалов
  (вспомогательный инструмент, не заменяет лингвистический анализ);
- **Отчёт** — сводный DOCX по разовому анализу (архив).

Часть вкладок (Стратификация, Тематика, НКРЯ, Тональность, старое
Сравнение, старый Отчёт, Профиль автора) скрыта в архив — их расчёты
питают профиль раздельного исследования и инспектор токенов. Вернуть
вкладку: убрать её индекс из списка `archived_pages` в `config.json`
и перезапустить программу.

---

## 7. Обновление словарных баз

Меню **Файл → 📚 Обновить словарные базы…**: диалог показывает подключённые
внешние словари (например, RuSentiLex), их версию и дату; «⬇ Обновить
выбранный словарь» скачивает свежую версию из открытого источника и
записывает метаданные в `data/lexicons_meta.json`. Обновление затрагивает
только словарные базы — на зафиксированные решения по делам не влияет.

## 8. Воспроизводимость и передача дела

- Все решения эксперта хранятся append-only: `feature_decisions`,
  `comparison_decisions`, `conclusion_decisions` + сквозной `audit_log`
  с версией программы у каждой записи.
- Импортированные файлы и экспортированные отчёты регистрируются с SHA-256
  — подмену материалов или правку отчёта после выгрузки можно доказать
  пересчётом хэша.
- Отчёт исследования содержит техническую справку: версия программы, хэш
  конфига фильтра детектора, версия правил пунктуации.
- Для передачи дела скопируйте `protocol.db` и папку с исходными файлами
  материалов.

## 9. Устранение неполадок

| Симптом | Причина / решение |
|---|---|
| «LT: недоступен» в сайдбаре | Нет Java 17+ или порт занят. Это не критично: собственные офлайн-детекторы (орфография, -тся/-ться, согласование, пунктуация, лексика) работают без LT. Для расширенного покрытия установите Java и нажмите «↻ Подключить LT» |
| PDF-кнопка неактивна | `pip install pypdf` и перезапуск |
| Импорт прошёл, но текст «мизерный» | Скан-PDF без текстового слоя или битый DOCX — нужен распознанный текст |
| Первый запуск долгий | Stanza качает модель (~100 МБ) — дождитесь одного раза |
| GigaCheck не стартует | Нужны transformers/torch и 8 ГБ+ ОЗУ; модель качается при первом запуске |
| Вкладки протокола пустые | Не создан проект или не выбран документ — начните с «Материалов» |
| Рекомендация «НПВ», хотя совпадения есть | Не добраны половинные корзины Огорелкова — список недоборов в пояснении |
