# Patch E.1 — Method-guided Comparison UI

Экран сравнительного исследования построен вокруг пары исходных текстов,
сохранённых evidence и экспертного решения. Он не запускает дополнительный
анализ и не меняет результаты `protocol/comparison.py`.

## Разделение сущностей

- `METHOD_FEATURE` — зарегистрированный методический признак; учитывается
  только после решения эксперта.
- `AUX_METRIC` — вспомогательный объективизирующий показатель; не входит в
  методический количественный счёт.
- `EVIDENCE` — наблюдение и контекст, на основании которого эксперт проверяет
  признак.
- `GENERAL_SKILL` — общий навык, показанный отдельно от частных признаков.

Уровень `NN/NS/NSV`, информативность по методическому источнику,
идентификационная значимость в конкретном исследовании и статус решения
хранятся и отображаются отдельно. `method_informativeness` переносится только
из прямого поля методреестра; при отсутствии такого поля показывается
`NOT_SPECIFIED` («не задана источником»).

TTR, hapax ratio, доли знаменательной/служебной лексики, средняя длина
предложения, соотношения частей речи и другие агрегатные статистические
показатели остаются `AUX_METRIC`. Инженерные Jaccard, синтаксическое и
агрегатное сходство из старого экрана сравнения не повышаются до
`METHOD_FEATURE` и в новый методический счёт не включаются.

## Evidence и трассировка

UI использует исходный слой документа и уже сохранённые evidence-фрагменты.
Точные совпадения получают координаты в своём документе и контекст
предложения. Если фрагмента нет (например, у средней длины предложения), UI
прямо сообщает, что локальная подсветка неприменима.

Для методического признака карточка показывает источник, раздел/страницу и
сохранённую в реестре формулировку. Отсутствующие сведения не достраиваются
эвристически.

## Аудит и совместимость

`comparison_decisions` остаётся append-only и дополнительно фиксирует эксперта,
старый и новый статус, старую и новую идентификационную значимость,
комментарий, версию программы и SHA-256-версию объединённого методреестра.
Legacy-поля `recommended_form` и `high_information` не удаляются. Старый
`high_information` сохраняется как `legacy_high_information`, но никогда не
интерпретируется как методически подтверждённый `HIGH`.
