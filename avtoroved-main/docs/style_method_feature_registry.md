# Canonical methodological style feature registry

> Patch C.1. Реестр METHOD_FEATURE не заменяет 32 legacy-метрики и не
> означает автоматического принятия признака экспертом.

Источник всех записей — сохранённые в проекте реестры методики Рубцовой и др.
(ЭКЦ МВД, 2007): `avtoroved2/data/features/registry_nn.yaml`,
`registry_ns.yaml`, `registry_nsv.yaml`. Формулировки и страницы перенесены
только из этих зарегистрированных источников; неподтверждённые позиции из
проектного списка не добавлялись.

Поля `method_reference_informativeness` и `expert_identification_value` здесь
отсутствуют намеренно. `AUTO` означает воспроизводимо формализуемое явление,
но любое срабатывание StyleEngineV2 всё равно создаётся с `accepted=false`.
`CANDIDATE_ONLY` требует контекстной проверки, `EXPERT_ONLY` автоматически не
детектируется. Пустой detector означает, что методический признак зарегистрирован,
но в текущем StyleEngineV2 активной реализации нет.

Всего: 62; AUTO: 26; CANDIDATE_ONLY: 18; EXPERT_ONLY: 18.

## Traceability contract

`method_feature_id → source registry → source wording/page → automation decision → active detector(s)`.

Legacy evidence links are stored separately in
`data/style_legacy_method_mappings.json`; they do not promote the corresponding
legacy row to METHOD_FEATURE. The strict methodological count remains guarded by
`role == METHOD_FEATURE`, an explicit expert `accepted` decision, METHOD source,
qualification, comparability, stability and linked evidence.
